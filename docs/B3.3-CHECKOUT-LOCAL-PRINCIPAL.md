# B3.3 · Checkout simulado en la instalación local principal

Esta implementación permite utilizar **la pantalla de pagos existente** de Tekora Móvil contra Laravel en `http://127.0.0.1:8000/api/v1`, sin cambiar de proyecto ni de puerto.

**No es una pasarela de pagos:** tarjeta y efectivo son estados de **prueba**. No se cobran tarjetas, no hay liquidaciones, y los resultados no acreditan dinero real. **No activar en producción ni en una VPS.**

## Seguridad y condiciones

- Deshabilitado por defecto: `TEKORA_LOCAL_DEMO_PAYMENTS=false`.
- Solo `APP_ENV=local`, configuración Laravel no cacheada, conexión SQLite, base principal exacta `database/database.sqlite`, petición HTTP de loopback con host localhost/127.0.0.1.
- El esquema de intentos de prueba es adicional, con nombre explícito `synthetic_checkout_attempts`; ninguna migración de producción lo crea.
- La configuración requiere un **comando explícito**, que genera un respaldo SQLite íntegro antes de crear la tabla. No elimina reservas, servicios, usuarios ni cotizaciones.
- La API exige Bearer del cliente propietario; el checkout requiere una cotización aceptada, una retención activa y el mismo protocolo de confirmación. No permite utilizar tarjetas reales.
- En repositorios y servidores compartidos deja la opción deshabilitada. El flujo anterior B3.2 con SQLite temporal sigue funcionando.

## Activación en Windows 11 (solo desarrollo local)

1. Guarda tu trabajo y verifica que solo tú usas la instancia local. Detén `php artisan serve` temporalmente antes de respaldar y crear el esquema.
2. En `C:\xampp\htdocs\TEKORA\.env`, añade **una sola vez**:

   `TEKORA_LOCAL_DEMO_PAYMENTS=true`

   Conserva `APP_ENV=local`, `DB_CONNECTION=sqlite`, y la base `database/database.sqlite`. **No cambies** `APP_KEY`, `DB_DATABASE` ni las cuentas.
3. Con PowerShell en `C:\xampp\htdocs\TEKORA` ejecuta:

   ```powershell
   php artisan config:clear
   php artisan tekora:local-demo-payments-setup
   ```

   Debe informar `Listo: intentos de pago ficticios habilitados solo en localhost` y la ruta del respaldo `database/backup-before-demo-payments-*.sqlite`. Si falla, **no** intentes crear la tabla manualmente.
4. Inicia de nuevo `php artisan serve --host=127.0.0.1 --port=8000`.
5. Conserva la URL de Expo `EXPO_PUBLIC_API_BASE_URL=http://127.0.0.1:8000/api/v1`, inicia `npx.cmd expo start --clear --web` y entra con una cuenta **cliente de pruebas**.
6. Recorre: solicitud aceptada → cotización aceptada → propuesta de fecha/hora → prestador acepta la retención de 900 s → reserva en móvil → `Elegir método de pago de prueba` → seleccionar tarjeta ficticia aprobada o efectivo → `Guardar método de prueba` → regresar y `Confirmar contratación`.
7. El comprobante de **prueba** se consulta en Cotizaciones. La tarjeta rechazada/fallo temporal no permite confirmar; efectivo seleccionado queda **pendiente**, no recibido.

## Desactivación

Cambiar `TEKORA_LOCAL_DEMO_PAYMENTS=false` y ejecutar `php artisan config:clear` deshabilita el checkout sintético de la base principal. **No elimines automáticamente** la tabla ni el respaldo; conserva el historial para revisar lo que se probó.

## Notas

- `Métodos de pago` en Mi cuenta es información de ayuda; no constituye una billetera ni abre una reserva. El checkout se presenta dentro de **una reserva elegible**, no como método global.
- Una reserva sin cotización o sin retención no tendrá este paso.
- Esta fase no cambia el contrato de pagos reales (aún no disponible). Antes de desplegar Tekora públicamente debe integrarse una pasarela legítima con confirmación de servidor, conciliación y reversos.
