# M3.1 · Validación de la API móvil

La base auditada es `6447fe67e581e63f5be70a2fe16b3833b37531f5`, merge de M3.0 en la PR #56. `php artisan route:list --json --path=api/v1` y OpenAPI contienen las mismas 49 operaciones, con métodos, rutas y requisitos Bearer concordantes. El recuento trata HEAD como el método implícito de GET. La auditoría no requirió cambios de esquema JSON ni de rutas. La guía del recorrido ya refleja las operaciones de reseñas de M2.9. El [inventario por pantalla](M3.1-ANDROID-HANDOFF.md#matriz-de-pantallas-y-endpoints) indica la evidencia de cada operación.

## Instalación limpia y relojes

En la base auditada, `php artisan migrate` sobre SQLite vacía con `CACHE_STORE=database` falló en `2026_11_19_000000_add_reservation_slot_holds` con `SQLSTATE[HY000]: General error: 1 no such function: tekora_booking_now_us`. El gestor de caché creó la conexión durante el arranque, antes del listener de `ConnectionEstablished` del proveedor de reservas. Las pruebas habituales usan caché en memoria y por ello no reproducían ese orden.

El proveedor registra ahora un conector SQLite de Laravel durante la fase de registro. El conector reutiliza la inicialización de Laravel y agrega el reloj a cada PDO que crea, incluido el de lectura cuando se configura por separado, y cualquier reconexión. El contrato de la función conserva microsegundos UTC en texto decimal con conversión SQL explícita a entero para evitar el truncamiento de PDO. Las pruebas verifican el comportamiento sin invocar manualmente el registro del reloj ni cambiar las migraciones, la duración B2 o las reglas de negocio.

### Reproducir en un clon desechable

Ejecuta en Bash dentro de un clon independiente de la rama de M3.1. Requiere PHP de 64 bits con PDO SQLite, Composer y Node con npm. El laboratorio crea una base exclusiva en un directorio nuevo. Los rangos de zona civil de la suite completa requieren una base de zonas horarias de PHP que reconozca los alias históricos del proyecto.

```bash
set -euo pipefail
test "$(git remote get-url origin)" = https://github.com/Fernando261/tekora-project.git
git merge-base --is-ancestor 6447fe67e581e63f5be70a2fe16b3833b37531f5 HEAD
test -z "$(git status --porcelain)"
for forbidden in .env .env.testing database/database.sqlite bootstrap/cache/config.php; do
    test ! -e "$forbidden"
done

m31_lab="$(mktemp -d)"
touch "$m31_lab/fresh.sqlite"
export APP_ENV=testing APP_CONFIG_CACHE="$m31_lab/config.php"
export DB_CONNECTION=sqlite DB_DATABASE="$m31_lab/fresh.sqlite" DB_URL=''
export DB_FOREIGN_KEYS=true CACHE_STORE=database
export SESSION_DRIVER=array QUEUE_CONNECTION=sync MAIL_MAILER=array

composer install --prefer-dist --no-interaction --no-progress
composer check-platform-reqs
npm ci
npm run build
php artisan migrate --force --no-interaction
php artisan migrate:status
php artisan migrate --force --no-interaction
php artisan route:list --json --path=api/v1 > "$m31_lab/routes.json"

php vendor/bin/phpunit --do-not-cache-result \
    tests/Feature/MobileCleanInstallationTest.php \
    tests/Feature/MobileIntegrationJourneyTest.php
unset TEKORA_PREFLIGHT_EVIDENCE
php vendor/bin/phpunit --do-not-cache-result
git diff --check
```

La prueba de instalación usa otro archivo temporal controlado. El recorrido y las pruebas habituales fuerzan SQLite `:memory:` con datos sintéticos. Las pruebas de concurrencia que necesitan procesos separados usan conexiones o archivos sintéticos propios. La segunda ejecución de las migraciones del laboratorio debe indicar `Nothing to migrate`.

## Cobertura de integración

- `MobileIntegrationJourneyTest` ejecuta 45 operaciones a lo largo del registro, login, perfil y foto, catálogo, conversación, cotización y reserva B2, avisos, realización explícita, reseña, retirada, historial y cierre de sesión. El prestador actúa mediante los servicios y permisos existentes. El mismo fixture compara reserva, recorrido, dashboard y avisos antes y después de transiciones. También comprueba aislamiento frente a otro cliente y a una cuenta dual que participa como prestador.
- La selección incluye recuperación, cancelaciones, aislamiento, solicitudes y mensajes idempotentes, versiones, filtros, paginación y los errores 401, 403, 404, 409, 422, 429 y 503. Incluye carreras concurrentes de solicitud, cotización, retención y reseña, además del límite exacto de 900 segundos.
- `Mobile API integration` ejecuta instalación desde los lock, build y la selección de integración y compatibilidad en PHP 8.2 y 8.4 sobre el SHA de la PR. El flujo `T1 isolated laboratory` verifica su laboratorio de concurrencia por separado.
- El registro y la recuperación ejercitan notificaciones sintéticas. Quedan por validar SMTP y su trabajador de cola con un buzón autorizado, el flujo en Android nativo y la conectividad DNS/TLS desde ese dispositivo. La fixture web B3.2 usa un método ficticio y sus propias pruebas. El flujo B2 de la API se valida con su contrato normal sin cobro.
