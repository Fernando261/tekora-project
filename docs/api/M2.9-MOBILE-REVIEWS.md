# M2.9 · Reseñas del solicitante móvil

Guía para Toño. Todas las rutas usan `/api/v1` sobre el origen HTTPS aprobado. Las lecturas públicas funcionan sin sesión. Las operaciones propias requieren un token Sanctum vigente del solicitante en `Authorization: Bearer …`. Una cuenta con roles combinados accede únicamente a sus reseñas como cliente.

| Operación | Método y ruta | Resultado |
|---|---|---|
| Reseñas de un servicio | `GET /services/{service}/reviews?page=1` | `200` con reseñas anónimas, total y promedio del servicio. |
| Reseñas de un prestador | `GET /providers/{provider}/reviews?page=1` | `200` con reseñas de sus servicios visibles. El promedio pondera cada reseña por igual. |
| Mis reseñas | `GET /reviews?page=1` | `200` con reseñas propias publicadas y retiradas. |
| Detalle propio | `GET /reviews/{review}` | `200` con el registro propio. |
| Publicar | `POST /reservations/{reservation}/review` | `201` en la primera publicación. `200` al reenviar el mismo contenido. |
| Retirar | `PATCH /reviews/{review}/withdraw` | `200` con el registro en estado `withdrawn`. Repetir el retiro conserva la primera fecha. |

## Lecturas y paginación

Envía `page` en la consulta. El valor predeterminado es 1 y el intervalo permitido es 1–10.000. Las páginas tienen 5 elementos para las lecturas públicas y 12 para las propias. La API ordena de la publicación más reciente a la más antigua, con orden estable por ID. Una página que supera `meta.last_page` devuelve `404`. Un conjunto vacío devuelve `200` en la página 1, con `total: 0` y `average_rating: null` en vistas públicas. Los demás parámetros de lectura devuelven `422`.

```json
{
  "data": [
    {"rating": 5, "comment": "La visita fue puntual.", "month": "enero de 2030", "service_id": 7, "service_title": "Soporte técnico"}
  ],
  "meta": {"current_page": 1, "per_page": 5, "last_page": 1, "total": 1, "average_rating": 5}
}
```

`total` y `average_rating` describen todo el conjunto publicable. El promedio se redondea a un decimal. La API entrega mes y año públicos y omite identidad del autor, ID de reseña, ID de reserva y fecha exacta. Las reseñas retiradas y las vinculadas a reservas o servicios que ya no cumplen las reglas no contribuyen al listado ni a los agregados. Un servicio oculto o un prestador sin servicios visibles devuelve `404`.

El historial propio conserva las reseñas retiradas y las de servicios cuya publicación se haya pausado. Sus metadatos de página incluyen `current_page`, `per_page`, `last_page` y `total`.

## Escrituras y reintentos

Para publicar envía `Content-Type: application/json` y un objeto como `{"rating":5,"comment":"La visita fue puntual."}`. `rating` es un entero JSON de 1 a 5. `comment` es opcional, admite `null` y tiene un máximo de 1.000 caracteres. El servidor guarda texto plano, normaliza los saltos de línea y trata el comentario vacío como `null`. El cuerpo y la consulta quedan reservados a los parámetros documentados. La publicación requiere la reserva propia con estado `completed`, que el prestador registra de forma explícita.

```json
{
  "data": {
    "id": 18, "reservation_id": 11, "service_id": 7, "service_title": "Soporte técnico",
    "rating": 5, "comment": "La visita fue puntual.", "status": "published",
    "created_at": "2030-01-07T16:00:00.000000Z", "withdrawn_at": null
  }
}
```

La reserva identifica el envío. Ante una respuesta perdida, repite la calificación y el comentario originales. Un reenvío equivalente devuelve `200` con el mismo ID y el estado vigente, también si la reseña se retiró. Cambiar el contenido después de publicar devuelve `409`. Para retirar acepta un cuerpo vacío o `{}`. `withdrawn_at` pasa a ser una fecha UTC y el comentario y la calificación se conservan en el historial privado.

| Estado | Interpretación en el cliente |
|---|---|
| `401` | Falta un token válido. Solicita iniciar sesión. |
| `403` | La cuenta o el token no cumple el acceso de solicitante. |
| `404` | Recurso no disponible. Una reseña o reserva ajena responde igual que una inexistente. |
| `409` | La reserva aún no se completó, el contenido difiere de la reseña previa o hay una escritura concurrente. Reconsulta la reserva y Mis reseñas. |
| `422` | Revisa `error.fields`. Por ejemplo, `rating` o `comment`. |
| `429` | Respeta `Retry-After`. Lecturas públicas hasta 120/minuto por IP. En privado, 120/minuto por actor y 480 por IP. Publicar y retirar comparten 10/minuto por actor y 40 por IP. |
| `503` | Servicio temporalmente no disponible. Reconsulta antes de repetir una escritura. |

```json
{"error":{"code":"conflict","message":"La operación entra en conflicto con el estado actual.","fields":{}}}
```

## Pantallas del cliente

En ficha de servicio y prestador, muestra promedio y total junto al listado. En el recorrido de una solicitud, `next_action.code=write_review` referencia la reserva y `view_review` referencia la reseña. Ambas acciones tienen `mobile_execution_available=true` cuando corresponden al solicitante. La escritura vuelve a verificar los permisos y el estado en el servidor. Mis reseñas puede ofrecer detalle, estado y una confirmación de retiro. Renderiza comentarios como texto plano y pide al usuario que evite incluir información personal en el texto público.

El texto público puede contener información que el autor haya escrito en el comentario. La app debe mostrar esa advertencia antes de publicar. Quedan pendientes las pruebas de paginación, texto plano y reintentos en el cliente nativo.

Para reproducir la validación en un clon aislado y sin `.env`, con dependencias de los archivos lock, ejecuta lo siguiente. El bootstrap de PHPUnit usa SQLite en memoria y datos sintéticos.

```bash
npm ci
npm run build
php vendor/bin/phpunit --do-not-cache-result tests/Feature/MobileReviewsTest.php tests/Feature/ReviewManagementTest.php tests/Feature/ReviewPublicVisibilityTest.php tests/Feature/ReviewConcurrencyTest.php
php vendor/bin/phpunit --do-not-cache-result
git diff --check
```
