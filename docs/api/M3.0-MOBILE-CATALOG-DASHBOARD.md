# M3.0 · Catálogo y panel del solicitante

Las tres lecturas se añaden a `/api/v1`. El catálogo sigue siendo público. El panel requiere un token Bearer Sanctum móvil con `client:read` y comprueba el rol y los permisos actuales de solicitante. Los límites existentes son 120 peticiones por minuto e IP para catálogo, y 120 por minuto y cuenta más un máximo de 480 por IP para lecturas privadas.

## Categorías

`GET /api/v1/categories` devuelve las categorías activas en el mismo orden que el catálogo web. Ordena por prioridad, nombre e identificador, de menor a mayor. Cada opción tiene únicamente `id`, `name` y `slug`. Una categoría activa puede existir sin servicios. Usa su `slug` en el filtro existente `GET /api/v1/services?category=soporte-tecnico`.

```json
{
  "data": [{"id": 1, "name": "Soporte técnico", "slug": "soporte-tecnico"}]
}
```

Sin categorías activas responde 200 con `{"data":[]}`. La consulta no admite paginación, filtros ni cuerpo.

## Servicios públicos de un prestador

`GET /api/v1/providers/7/services?page=1&per_page=12` devuelve servicios públicos del perfil 7, con el contrato de `GET /api/v1/services` y orden de identificador descendente. El perfil carece de visibilidad pública si no tiene al menos un servicio publicado en una categoría activa con rol de prestador vigente. Los perfiles inexistentes o sin visibilidad devuelven 404.

```json
{
  "data": [{
    "id": 21,
    "title": "Soporte de computadoras",
    "description": "Diagnóstico remoto.",
    "modality": "remote",
    "category": {"id": 1, "name": "Soporte técnico", "slug": "soporte-tecnico"},
    "provider": {"id": 7, "display_name": "Soporte local", "headline": "Especialista en equipos", "bio": "Diagnóstico y mantenimiento."},
    "price": null
  }],
  "meta": {"current_page": 1, "per_page": 12, "last_page": 1, "total": 1}
}
```

`page` admite enteros del 1 al 10000 y empieza en 1. `per_page` admite enteros del 1 al 50 y por defecto vale 12. Una página válida posterior a `last_page` devuelve 200 con `data` vacío y la misma información de paginación. Los filtros adicionales y los cuerpos de petición devuelven 422. `price` usa el esquema `PublishedPrice` y la versión pública vigente. Un servicio sin precio publicado devuelve `null`.

Para la ficha nativa usa `GET /api/v1/providers/7` para los datos del perfil, la ruta nueva para sus servicios y `GET /api/v1/providers/7/reviews` para las reseñas públicas. La app puede abrir el detalle existente de cada servicio con su `id`.

## Inicio y actividad del solicitante

`GET /api/v1/me/dashboard` toma una instantánea de la cuenta del token. No admite parámetros ni cuerpo. Incluye únicamente actividad como solicitante, incluso si la cuenta también ejerce como prestador.

```json
{
  "data": {
    "as_of": "2030-01-01T12:00:00.000000Z",
    "timezone": "America/Mexico_City",
    "counts": {
      "active": 2,
      "confirmed": 1,
      "requested": 0,
      "completed": 1,
      "cancelled": 0,
      "held": 1,
      "unread_conversations": 1,
      "unread_notifications": 2
    },
    "upcoming_reservations": [{
      "id": 14,
      "inquiry_id": 92,
      "service_id": 21,
      "title": "Soporte de computadoras",
      "status": "confirmed",
      "starts_at": "2030-01-07T15:00:00.000000Z",
      "ends_at": "2030-01-07T16:00:00.000000Z"
    }],
    "recent_inquiries": [{
      "id": 92,
      "service_id": 21,
      "title": "Soporte de computadoras",
      "status": "accepted",
      "created_at": "2029-12-30T19:00:00.000000Z"
    }]
  }
}
```

| Campo en `counts` | Qué cuenta |
|---|---|
| `active` | Solicitudes `pending` o `accepted`. |
| `confirmed` | Reservas `confirmed` con inicio posterior a `as_of`. |
| `requested` | Propuestas `requested` con inicio futuro y sin retención. |
| `held` | Retenciones `held` con vencimiento estrictamente posterior a `as_of`. |
| `completed` | Reservas en estado `completed` tras registrar su realización. |
| `cancelled` | Reservas en estado `cancelled`. |
| `unread_conversations` | Conversaciones propias con al menos un mensaje recibido posterior a su marcador de lectura. |
| `unread_notifications` | El mismo contador del solicitante que `GET /api/v1/notifications/unread-count`. |

Con una cuenta sin actividad, los contadores valen 0 y las dos listas están vacías. La agenda muestra hasta cinco reservas confirmadas ordenadas por inicio e identificador ascendente. Las cinco solicitudes más recientes se ordenan por creación e identificador descendente e incluyen los estados `pending`, `accepted`, `rejected`, `cancelled` y `completed`. Los timestamps se entregan en UTC. Formatea las fechas de la pantalla de inicio con `timezone` y usa el huso horario propio de la reserva si lo presenta su detalle.

Usa los identificadores de la respuesta para enlazar pantallas nativas y consultar `GET /api/v1/reservations/{reservation}` o `GET /api/v1/inquiries/{inquiry}`. Los contadores y listas se leen juntos en una transacción. La respuesta carece de URLs de vistas HTML.

### Retenciones

La aceptación B2 inicia la retención de 900 segundos en el servidor. Una retención sale de `held` al llegar a su vencimiento, tampoco vuelve a `requested` y se muestra en la agenda únicamente si la contratación se confirmó y el inicio sigue siendo futuro. La lectura del panel no escribe transiciones. Para mostrar la cuenta regresiva o actuar sobre una reserva, usa su detalle existente, que entrega los datos del protocolo B2. Actualiza el panel al volver a primer plano o después de una operación de reserva.

Si el reloj retrocede respecto del último instante registrado por el sistema de reservas, o si falta información por un fallo de almacenamiento, la respuesta es 503 sin contadores parciales. La app debe indicar que la información no está disponible y permitir reintentar sin convertir el fallo en un estado vacío.

## Errores y contratos

| HTTP | Código JSON | Cuándo ocurre |
|---|---|---|
| 401 | `unauthenticated` | El panel requiere un Bearer válido. |
| 403 | `forbidden` | El token o la cuenta carecen de permisos actuales de solicitante. |
| 404 | `not_found` | El prestador no existe o no es visible. |
| 422 | `validation_failed` | Parámetro fuera de rango, parámetro desconocido o cuerpo enviado a la lectura. |
| 429 | `rate_limited` | Se alcanzó el límite. Espera el intervalo de `Retry-After`. |
| 500 | `server_error` | Fallo inesperado. |
| 503 | `temporarily_unavailable` | No se pudo consultar el almacenamiento o verificar el reloj del panel. |

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Los datos enviados no son válidos.",
    "fields": {"request": ["La petición contiene parámetros no permitidos."]}
  }
}
```

Puedes ejecutar las peticiones del [archivo HTTP](examples/M3.0-mobile-catalog-dashboard.http) en un clon aislado con datos sintéticos. Consulta también [OpenAPI](openapi.json) y la [matriz de paridad](PARIDAD-CLIENTE-MOVIL.md).
