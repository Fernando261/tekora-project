Base obligatoria verificada: `00798bfab31f6608760ec252ac20e15573f8e5ce`, tanto en GitHub como en `HEAD` y `origin/main` antes de modificar código. Rama: `codex/w62b-tekora-only`. Entrega mediante un único PR en borrador; sin fusión, despliegue ni auto-merge.

- Acceso de lectura al repositorio confirmado mediante GitHub y `git ls-remote origin refs/heads/main`.

- El alcance se recuperó de [W62A](W62A.md) y sus inventarios integrados. No se empezó W6.2c.

## Resultado de producto y contratos

Solo queda la experiencia Tekora: cuenta central, catálogo, perfiles de prestadores, solicitudes, conversaciones, avisos, disponibilidad, reservas, reseñas y API móvil. Se retiran inicio emocional, PDF, comunidad, conferencias, recordatorios, citas anteriores, directorio/panel profesional separado y Calendar/OAuth. No se crea una pantalla de archivo ni se convierten registros anteriores en actividad nativa.

Se eliminan las **32 operaciones inventariadas**, sus nombres y sus consumidores. La decisión de cierre es retirar las rutas: **404**, también con sesión anterior o usuario central autenticado. No hay redirects de escrituras, alias, replay, compatibilidad permanente ni handler de cierre que consulte datos. Los GET retirados tampoco conservan una ruta HEAD implícita. `/cuenta/citas` desaparece; el permiso `client.appointments.view` continúa protegiendo `/cuenta/cliente`.

El callback Google en vuelo devuelve 404 sin intercambiar el código, renovar tokens ni ejecutar consultas de dominio. Desaparecen guard/proveedor `profesionista` y configuración de consumo Google; una sesión anterior no autentica `web`. **No se revocan credenciales, desconectan cuentas externas ni modifican eventos remotos**. El código no pretende resolver efectos externos anteriores; no se ejecutó ninguna conexión real.

Se quitan el selector profesional del login/registro, el grupo de navegación anterior, el enlace del footer, la tarjeta cliente y el bloque del perfil. Los formularios centrales, intención de registro, roles, policies, throttle, CSRF, POST logout, CSP, contadores y navegación nativa conservan sus contratos. La activación mantiene el aviso de que no es una verificación profesional.

## Límites verificados

`composer audit` no pudo completar su consulta a `https://packagist.org/api/security-advisories/`: el proxy devuelve **403 CONNECT**. No se presenta como una auditoría aprobada ni se cambió la política de red. Se realizó una comprobación independiente de los metadatos oficiales `https://repo.packagist.org/p2/<paquete>.json`: **113 paquetes (78 producción, 35 desarrollo), cero avisos aplicables**, comparando `affectedVersions` con Composer Semver. El [resultado](evidence/W62B-packagist-metadata-check.json) incluye URL, checksum de cada respuesta, versión y número de avisos publicados. Este contraste no comprueba abandono ni sustituye el informe completo de `composer audit`; repetir ese comando cuando la API esté permitida.

En Chromium, la órbita decorativa de la portada produce un ancho documental de **1051 px a 1024 px** y **1131 px a 1100 px**. Ambos valores se reprodujeron idénticos en la base inmutable y en W6.2b. No hay una nueva regresión de ancho; se registra la limitación existente sin modificar el diseño en esta retirada. [Matriz y comparación](evidence/W62B-browser-results.json). En los otros 117 casos no se detectó desbordamiento horizontal. Axe es una comprobación automática y no certifica accesibilidad completa.

La validación independiente Windows/Laragon/PHP 8.2 queda pendiente; [guía aislada](W62B-LARAGON.md). No se certifica un upgrade MySQL ni se inspeccionó la configuración de una instalación real.

Las primeras ejecuciones exploratorias no son resultados de aceptación: una corrió mientras se editaba el checkout y otra copia inicial de vendor coincidió con su actualización. Ambas se descartaron y la baseline se reinstaló desde su lock en un export inmutable. También se regeneraron los HTML del preview tras el build final para evitar referencias a hashes de assets anteriores. Los resultados de la tabla corresponden exclusivamente a ejecuciones completadas con fuentes y dependencias estables.

## Reproducción

1. En un clon aislado de esta rama, instalar los locks con Composer y npm; ejecutar `npm run build` antes de la suite completa.
2. Ejecutar `php vendor/bin/phpunit --do-not-cache-result`. Su bootstrap falla antes de migrar si no usa SQLite `:memory:`.
3. Ejecutar `php tools/tekora-w5-preview.php <directorio-temporal-nuevo> http://127.0.0.1:8080` y servirlo con `TEKORA_W5_PREVIEW_DIR` mediante `tools/tekora-w5-preview-router.php`. El router admite solo GET/HEAD y no arranca Laravel.
4. Generar y servir otro export desde el SHA base con sus propios locks/bundles, por ejemplo en el puerto 8081. No reutilizar bundles posteriores para la base.
5. Ejecutar `python tools/tekora-w62b-browser-checks.py --base-url http://127.0.0.1:8080 --baseline-url http://127.0.0.1:8081 --pages <export-nuevo> --axe <axe.min.js> --output <resultados-nuevos>`. Requiere Playwright, Chromium y axe-core (se usó axe 4.14).

Los [logs y resultados](evidence/W62B-validation.json), el JUnit y las capturas sintéticas de [login móvil](evidence/W62B-login-375.png), [perfil](evidence/W62B-profile-photo-1440.png), [cliente móvil](evidence/W62B-client-dashboard-375.png) y [prestador](evidence/W62B-provider-dashboard-1440.png) acompañan el cambio. No ejecutar estos pasos contra producción, ni importar `.env`, SQLite, uploads o credenciales de otra instalación.
