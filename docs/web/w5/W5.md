# Tekora W5 · Cinematic Identity & Account

W5 moderniza el centro de cuenta, activación de prestador, perfil privado, nombre, catálogo administrativo de roles, recuperación de contraseña y tres errores autónomos. Conserva la lógica de identidad aprobada, las cuentas históricas y los contratos HTTP.

Base: `521a081b039d8f8ee4d25a9e8936eb6ca4c0de05`. Rama: `codex/web-w5-cinematic-identity`. PR nuevo en borrador; no fusionar ni desplegar. Los SHA de implementación y entrega se registran al publicar el PR. [Guía Windows/Laragon](W5-LARAGON.md) · [Inventario MindBloom y hallazgo de foto](W5-MINDBLOOM-INVENTORY.md).

## Diseño e implementación

El namespace `.tk-identity` y sus dos entradas Vite son opt-in. Se incorporan cinco componentes: `identity-assets`, `identity-heading`, `identity-scene`, `identity-avatar`, `identity-error-layout` y sus variantes mediante propiedades y clases compartidas. Las tarjetas de experiencia, datos, activación, validación y catálogo se componen en las vistas con controles HTML nativos.

Las escenas de **identidad**, **perfil** y **seguridad** usan perspectiva de 1000 px, `preserve-3d`, planos a distinta profundidad, rotaciones, órbitas y geometría propia. No contienen datos del usuario. Solo la decoración recibe entrada WAAPI y parallax acotado; el puntero no mueve botones, formularios ni datos. Touch y movimiento reducido permanecen estáticos. No hay WebGL, Three.js, frameworks, paquetes o fuentes remotas nuevos.

La marca, cristales oscuros, cian, superficies y navegación continúan W1–W4. La recuperación reutiliza `access-layout` y `tekora-auth-card`. Los componentes compartidos tienen `identity=false` por defecto; los consumidores aprobados no cargan W5. Perfil y editor usan `ambient=false` para conservar el contrato histórico probado por W1, con fondo y escena W5 propios. Ninguna prueba antigua cambia.

Los alias locales «Tekora Identity Body/Display», con `font-display: optional`, evitan el intercambio tardío que desplazaba la recuperación durante el ensayo inicial. Los archivos de fuentes y los 14 bundles aprobados anteriores permanecen idénticos. [Tamaños y comparación](evidence/asset-budget.json): CSS W5 **15.017 B** (gzip **3.644 B**); JS **1.746 B** (gzip **816 B**). El presupuesto es 16 KiB CSS / 3 KiB JS minificados; se cumple.

## Contratos e identidad

| Superficie | Preservación verificada |
| --- | --- |
| `/cuenta` y activación | Mismos `@can`, POST `identity.roles.store`, CSRF, roles existentes e idempotencia; GET no activa roles; no autoasignación de administrador |
| `/perfil` | Guard `web`, datos privados y campos actuales; avatar funcional usa `Storage::url(profile_photo_path)`; no PII en geometría, atributos de escena ni telemetría |
| Foto | `photo`, multipart, CSRF, JPG/JPEG/PNG/WebP, máximo 2048 KB, disco `public`, referencia y mensajes originales; input y envío explícito funcionan sin JS |
| Nombre | Ruta y PUT originales, `name`, máximo 255, errores y `old()` escapados; entradas array no causan error de renderizado |
| Recuperación | POST/broker, token oculto, email/password/confirmation, expiración, hashing, validación y vuelta al login intactos; JS no lee ni persiste credenciales |
| Roles | Solo consulta autorizada, nombres reales, sin edición ni usuarios nuevos expuestos |
| Histórico | Sin unir `users`/`profesionistas`; pruebas con mismo correo preservan credenciales independientes; enlaces anteriores identificados por su procedencia |
| Errores | Cliente/prestador/419 autónomos, sin navegación/consultas a BD; mismos mensajes, estado y regreso, sin SQL ni detalles internos |

La CSP W5 en testing/producción exige scripts locales, sin inline/eval; en local se conserva compatibilidad con Vite. La política existente de estilos inline se conserva. No se añaden cabeceras de middleware ni se afirma una política `frame-ancestors` mediante meta. Los fallbacks pueden cargar CSS sin JS y no consultan usuarios ni contadores.

No cambian rutas, controladores, servicios, modelos, policies, guards, middleware, API, migraciones, validaciones, contratos HTTP, dependencias ni lockfiles. No se modifica `.env`, APP_KEY ni BD persistentes. Las fotos de prueba y export se escriben únicamente en discos falsos temporales. El servidor visual sirve HTML estático y no inicia Laravel.

Esto describe la cadencia del laboratorio con renderizado software; no acredita 60 FPS ni equivale a INP o GPU real. Touch y preferencias reducidas se verifican estáticos en la matriz funcional.

El baseline histórico de perfil/editor/recuperación referencia Google Fonts y scripts inline que el router estático bloquea con su CSP local. Se registran esos recursos fallidos en el baseline; por ello la comparación es una prueba local offline, no una estimación de producción con fuentes remotas disponibles. W5 no presenta recursos fallidos inesperados. La tipografía optional puede conservar fallback en una primera carga lenta para priorizar estabilidad; no se promete el mismo aspecto tipográfico bajo cualquier red.

Chromium Linux utiliza renderizado software; quedan pendientes Windows/Laragon físico, GPU real, NVDA y aprobación visual independiente. Axe no sustituye una revisión humana de accesibilidad. No se envió correo real, no se usó una instalación persistente y no se afirma validar proveedores externos.
